01Descripción general

¿Qué es THE DROP?

THE DROP es una plataforma de e-commerce de streetwear compuesta por una aplicación móvil multiplataforma (.NET MAUI) conectada a un backend de microservicios. Permite a los usuarios explorar productos, agregar al carrito, seleccionar modalidad de pago y completar compras reales a través de la pasarela OpenPay.

Frontend
.NET 10 MAUI
Android / iOS / Windows
Backend
.NET 8 Minimal APIs
2 microservicios + gateway
Infraestructura
Docker + RabbitMQ + SQL Server
Event-driven architecture

03Microservicio ms-ordenes

Responsabilidades

  • Recibir solicitudes de creación de órdenes desde el API Gateway
  • Aplicar reglas de descuento automático según subtotal y tipo de producto
  • Calcular meses sin intereses según modalidad de pago
  • Persistir la orden en SQL Server (esquema ordenes)
  • Publicar el evento orden.creada en RabbitMQ
  • Escuchar eventos pago.aprobado y pago.rechazado para actualizar el estado
  • Implementar idempotencia mediante Idempotency-Key header

04Microservicio ms-pagos

Responsabilidades

  • Escuchar el evento orden.creada desde RabbitMQ
  • Crear un registro de pago pendiente en SQL Server
  • Llamar a la API de OpenPay con el token de tarjeta para procesar el cobro

05API Gateway

Características

  • YARP (Yet Another Reverse Proxy) — enrutamiento hacia microservicios
  • JWT Authentication — valida Bearer token en cada request protegido
  • Rate Limiting — políticas: public, authenticated, strict
  • CORS — configurado para clientes autorizados
  • Health Checks — monitoreo de microservicios en /health
  • Serilog — logging estructurado a consola y archivos
  • Correlation ID — trazabilidad de requests entre servicios

09Flujo completo de una compra

1. Usuario abre la app y hace login (se genera JWT con HMACSHA256) 2. Explora productos (cargados desde SQLite local) 3. Agrega productos al carrito (ICartService en memoria) 4. En CartPage selecciona modalidad de pago y presiona CONFIRMAR 5. Navega a PaymentPage → ingresa datos de tarjeta 6. → OpenPayTokenService llama POST /tokens con public key ← OpenPay devuelve card_token 7. → OrdenService llama POST /api/ordenes al API Gateway Header: Authorization: Bearer JWT Header: Idempotency-Key: UUID Body: { usuarioId, modalidadPago, cardToken, items[] } 8. → API Gateway valida JWT → rutea a ms-ordenes :5001/ordenes 9. ms-ordenes: - Verifica idempotencia (evita duplicados) - Calcula descuentos según reglas de negocio - Inserta en ordenes.ordenes con estado "pendiente" - Publica OrdenCreadaEvent en RabbitMQ (tienda.ordenes → orden.creada) 10. ms-pagos recibe OrdenCreadaEvent: - Crea registro de pago "pendiente" en pagos.pagos - Llama POST /charges a OpenPay con card_token y private_key - Si aprobado: actualiza pago a "aprobado", publica pago.aprobado - Si rechazado: actualiza pago a "rechazado", publica pago.rechazado 11. ms-ordenes recibe evento: - pago.aprobado → orden.Estado = "confirmada" - pago.rechazado → orden.Estado = "cancelada" 12. App navega a OrderTrackingPage con el ID de orden real (#42)
